# BoardingBook

Student boarding / roommate platform for SLIIT: listings and search, roommate matching, booking requests and agreements, rent payments with receipts, chat, owner and admin dashboards.

| Part | Stack | Hosted on |
|---|---|---|
| Frontend (`/`) | React 18, Vite, Tailwind | Vercel |
| Backend (`/backend`) | Node 20, Express, Socket.io, MongoDB (Mongoose) | Render |
| Database + file storage | MongoDB Atlas (files are stored in GridFS) | Atlas |

## Run locally

```bash
# Backend
cd backend
cp .env.example .env      # fill in MONGO_URI and JWT_SECRET
npm ci
npm run dev               # http://localhost:5001/api/health

# Frontend (new terminal, repo root)
cp .env.example .env      # VITE_API_URL=http://localhost:5001
npm ci
npm run dev               # http://localhost:5173
```

## Deploy

### Backend → Render
1. Render dashboard → **New → Blueprint** → select this repo. It reads `render.yaml`.
2. Enter the secret values when asked:
   - `MONGO_URI` — Atlas connection string. In Atlas → Network Access, allow `0.0.0.0/0` (Render has no fixed IP on the free plan).
   - `RESEND_API_KEY` — optional; without it emails (password reset) are only logged.
3. Deploy, then open `https://<service>.onrender.com/api/health` — it should show `"db":"connected"`.

`JWT_SECRET` is generated by Render. `FRONTEND_URL` / `CORS_ORIGIN` default to `https://bording-book.vercel.app`; change them if the site lives elsewhere (comma-separate several origins).

> Free Render instances sleep after ~15 minutes idle; the first request afterwards takes ~30–60 s.

### Frontend → Vercel
In the Vercel project → **Settings → Environment Variables** add
`VITE_API_URL = https://<service>.onrender.com`, then redeploy.

### Email
Password-reset emails go through [Resend](https://resend.com). To email any address, verify a domain in Resend and set `EMAIL_FROM` (for example `BoardingBook <noreply@mail.yourdomain.com>`). With the default `onboarding@resend.dev` sender, Resend only delivers to your own Resend account address.

## Security notes
- Never commit `.env` files — only the `.env.example` templates.
- Uploaded files (payment slips, KYC documents, chat attachments, receipts, agreements) are stored in MongoDB GridFS, so they survive Render restarts and redeploys.
